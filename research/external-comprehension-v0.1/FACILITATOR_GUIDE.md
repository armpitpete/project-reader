# Facilitator Guide

Purpose: collect directional evidence about whether real people understand and trust the deployed Project Reader surface. This is not a teaching session, a medical assessment, scientific validation, or population research.

Session length: approximately 15-20 minutes.

Use one anonymous participant ID: `R01`, `R02`, `R03`, `R04`, or `R05`.

## Locked Comprehension Repository

Use the same repository for every R01-R05 comprehension session:

- ordinary GitHub page: https://github.com/armpitpete/sample-hold-lab
- Project Reader input: `armpitpete/sample-hold-lab`

Do not switch repositories during the matched before-and-after questions. The paid-outcome test remains separate and may involve a different real public repository only under the rules in `PAID_OUTCOME_TEST.md`.

## Ground Rules

- Project Reader is being tested, not the participant.
- The participant may stop at any time without giving a reason.
- Record only broad self-described context: non-technical, young person, neurodivergent, or overlapping categories.
- Do not record names, email addresses, phone numbers, medical diagnoses, school or workplace names, or other unnecessary identifying details.
- Keep participant statements separate from facilitator interpretation.
- Do not explain the repository, GitHub, or Project Reader answers before the participant has tried each step.
- If help is requested, record the exact help requested and the help actually given.

## Setup

1. Open a normal browser session. Do not sign in to GitHub.
2. Have the ordinary GitHub page ready: https://github.com/armpitpete/sample-hold-lab.
3. Have Project Reader ready: https://armpitpete.github.io/project-reader/.
4. Have a timer ready for the GitHub baseline inspection.
5. Have a blank record ready outside Git if you will write real session details.
6. Keep this guide visible only to the facilitator.

## Consent And Anonymity Wording

Read this before starting:

> I am testing Project Reader, not testing you. I want to see what makes sense, what is confusing, and whether the page gives enough trust evidence. I will use an anonymous ID such as R01, not your name. Please do not give me personal, medical, school, workplace or contact details. You can stop at any time, skip any question, or ask me to delete a note before we finish.

Ask:

1. Is it okay to take anonymous notes about what you say and do during this short session?
2. Do you understand that you can stop at any time?

If either answer is no, stop the session and record only that the session did not proceed.

## Context Questions

Ask these before the baseline inspection. Record them as context only; they are not substitutes for the matched comprehension questions.

1. How comfortable do you usually feel reading a GitHub project page?
2. If a tool explained a project to you, what would make you trust or distrust it?

Do not ask the participant to guess what "Project Reader" might do.

## Before Project Reader: Ordinary GitHub Baseline

1. Show the participant the ordinary public GitHub repository page for `armpitpete/sample-hold-lab`.
2. Allow up to three minutes of natural inspection without explanation or help beyond basic navigation.
3. Record time used, exact help requested, help actually given, and whether the participant could form an answer.
4. Ask the six matched baseline questions:
   - In your own words, what is this project?
   - What, if anything, appears finished?
   - What, if anything, appears unfinished or uncertain?
   - How complete do you think it is? Use your own words; a percentage is not required.
   - How likely do you think the current plan is to be finished?
   - What evidence makes you trust or distrust those answers?

Record verbatim answers or close transcription. If the participant cannot answer, record that as the participant's statement. Record confidence only if the participant naturally expresses it; do not ask for a confidence score.

## Using Project Reader

Then show the deployed Project Reader surface with the same repository already entered, or provide the exact value `armpitpete/sample-hold-lab`. Do not switch repositories.

Say:

> Please use this page as naturally as you can. Say what you are looking at and what you think it means. I may ask what you are trying to find, but I will not explain the page unless you ask for help.

Use only neutral prompts:

- What are you looking for now?
- What do you think this part means?
- What would you do next?
- Is there anything you want to open or ignore?
- What, if anything, feels unclear?

Do not ask leading prompts such as "Can you see the evidence section?" or "Do you understand that this means it is complete?"

## What To Observe

Record:

- whether the participant understands the first screen without opening details;
- whether they use optional disclosure controls;
- any hesitation, rereading, backtracking or visible confusion;
- any mistaken interpretation of completion, likelihood, evidence, technology, contact or limitations;
- any request for help;
- time to first useful answer about what the project is or what state it is in;
- whether the participant can identify at least one reason to trust or not trust the result.

Hesitation means a pause, repeated rereading, uncertainty, backtracking, or asking for confirmation. Do not treat quiet reading as hesitation unless the participant shows uncertainty or delay that affects the task.

Help requested means the participant asks for explanation, navigation help, technical help, or confirmation. Record the request before answering.

## After Project Reader: Matched Questions

Ask the same six questions again, with identical core wording, before any extra usability questions:

1. In your own words, what is this project?
2. What, if anything, appears finished?
3. What, if anything, appears unfinished or uncertain?
4. How complete do you think it is? Use your own words; a percentage is not required.
5. How likely do you think the current plan is to be finished?
6. What evidence makes you trust or distrust those answers?

Record answers as participant statements. Add facilitator interpretation only in the separate comparison and interpretation fields after the session.

## Extra Usability Questions

Ask these only after the matched after-Project-Reader questions are complete:

1. What would you change to make the page easier to understand?
2. Would you trust this enough to use it for another public GitHub project? Why or why not?
3. Was there any point where you felt stuck, rushed, or unsure what to do?

## Paid-Outcome Prompt Boundary

Use `PAID_OUTCOME_TEST.md` only after the participant has seen the public example and the exact deliverable description. Do not pressure, negotiate, create payment links, or reinterpret polite interest as commitment.
