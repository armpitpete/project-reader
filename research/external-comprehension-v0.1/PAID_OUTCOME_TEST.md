# Paid-Outcome Test Card

Use one offer only:

**Owner-ready Project Reader report - £25 trial price**

## Offer

For one supported public GitHub repository, Merrin will deliver a plain-English Project Reader report that explains:

- what the project is;
- what appears complete;
- what remains;
- what evidence supports those statements;
- what likelihood evidence exists or is unknown;
- what technologies appear in the public repository;
- what remains uncertain.

Delivery: permanent HTML or PDF report within three working days.

Included: one factual correction pass.

Excluded:

- private repository access;
- account setup;
- repository changes;
- ongoing monitoring;
- strategic consultancy;
- payment infrastructure or contracts created during this test.

Refund position: if the report is not delivered within three working days, or it does not cover the agreed public repository, the buyer can decline to pay or ask for the trial payment back.

This is a demand test, not a claim that £25 is the final market price.

## When To Make The Offer

Make the offer only after the prospective buyer has seen:

1. the public Project Reader example at https://armpitpete.github.io/project-reader/;
2. the exact deliverable description above;
3. the exclusions above.

Do not offer private-repository work. Do not create a payment link. Do not request account access. Do not imply that a report already exists.

## Offer Script

Say:

> There is one trial offer for this test. For £25, Merrin can prepare an owner-ready Project Reader report for one supported public GitHub repository. It would be delivered as a permanent HTML or PDF report within three working days, with one factual correction pass included. It does not include private repository access, account setup, repository changes, ongoing monitoring or consultancy. After seeing the example and this description, would you pay £25 for that report for a real public repository you care about?

If they ask for clarification, repeat only the offer, delivery, exclusions and refund position. Do not negotiate the offer or add extras.

## Honest Result Recording

Record exactly one result:

- `paid` - real payment was made or unambiguously handed over for the £25 report.
- `explicit_commitment` - the person says a clear equivalent of "yes, I will buy at £25" for a real public repository, but payment is not taken in the session.
- `refused` - the person says no, maybe, not now, asks for a different price or scope, or does not commit.

Use the participant's words where possible. Do not reinterpret a polite positive comment as commitment.

Examples:

- "This is interesting" = `refused` unless they also explicitly agree to buy.
- "I might use it later" = `refused`.
- "Yes, I will buy that for my public repo at £25" = `explicit_commitment`.
- Real payment for the described report = `paid`.

Do not create false testimonials, simulated buyers, synthetic demand evidence, payment accounts, contracts, payment links, private access, or follow-up claims.
